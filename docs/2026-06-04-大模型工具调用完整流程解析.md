# 大模型工具调用完整流程解析

> 创建日期: 2026-06-04

## 1. 核心概念

### 1.1 什么是 Tool Calling（工具调用）

Tool Calling 是 OpenAI API 提供的一种能力：你在请求中告诉大模型"你有这些工具可用"，大模型根据用户的输入**自主决定**是否调用某个工具、调用哪个工具、以及传什么参数。

**关键点**：大模型不是直接执行工具，而是**告诉你它想调用什么工具**。然后由你的代码去执行，再把结果告诉它。

### 1.2 三种消息角色

| 角色 | 谁发的 | 作用 |
|------|--------|------|
| `user` | 用户 | 用户说的话 |
| `assistant` | 大模型 | 大模型的回答（或工具调用意图） |
| `tool` | 你的程序 | 工具执行结果，返回给大模型 |

## 3. 详细步骤拆解

### 步骤 1: 程序启动，注册工具

**文件**: `cmd/main.go:28`

```go
tools := internal.GetTools()
```

`GetTools()` 返回 4 个工具定义（`tools.go:27-109`），每个工具包含：
- `name`: 工具名称
- `description`: 告诉大模型这个工具是干什么的
- `parameters`: 工具需要哪些参数、哪些是必填的

**关键理解**：此时只是**告诉大模型**你有这些工具，并没有执行任何操作。

### 步骤 2: 用户输入，加入消息历史

**文件**: `cmd/main.go:71`

```go
messages = append(messages, openai.UserMessage(input))
```

用户说 `"帮我看看 main.go 的内容"`，变成一条 `user` 消息放入历史。

### 步骤 3: 调用 LLM，发送消息 + 工具列表

**文件**: `llm.go:46-50`

```go
stream := c.client.Chat.Completions.NewStreaming(ctx, openai.ChatCompletionNewParams{
    Model:    c.model,
    Messages: messages,   // ← 所有历史消息
    Tools:    c.tools,    // ← 工具定义列表
})
```

这里发送的 HTTP 请求体大致如下（简化）：

```json
{
  "model": "gpt-4o",
  "messages": [
    {"role": "user", "content": "帮我看看 main.go 的内容"}
  ],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "read_file",
        "description": "Read the contents of a file...",
        "parameters": {
          "type": "object",
          "properties": {
            "path": {"type": "string", "description": "The path to the file..."}
          },
          "required": ["path"]
        }
      }
    },
    ...其他工具...
  ]
}
```

### 步骤 4: LLM 决定是否调用工具

LLM 收到请求后，根据你的用户输入和工具描述，**自主决定**：
- 不需要工具 → 直接返回文字回复
- 需要工具 → 返回 `tool_calls` 数组

比如 LLM 认为"用户想看文件内容"，所以决定调用 `read_file`：

```json
{
  "role": "assistant",
  "content": null,
  "tool_calls": [
    {
      "id": "call_abc123",
      "type": "function",
      "function": {
        "name": "read_file",
        "arguments": "{\"path\":\"main.go\"}"
      }
    }
  ]
}
```

**关键理解**：`id` 是 LLM 生成的唯一标识符，后续你要用这个 `id` 把结果关联回去。

### 步骤 5: 我们的代码解析流式响应

**文件**: `llm.go:55-86`

流式响应是**分块**返回的。`tool_calls` 的 JSON 参数可能被拆成多个 chunk。代码用 `toolCallIndices` 做索引映射，把碎片拼起来：

```go
for stream.Next() {
    chunk := stream.Current()
    delta := chunk.Choices[0].Delta

    for _, tc := range delta.ToolCalls {
        idx := int(tc.Index)
        if _, exists := toolCallIndices[idx]; !exists {
            // 第一次见到这个 tool_call，创建新条目
            toolCallIndices[idx] = len(toolCalls)
            toolCalls = append(toolCalls, ...)
        } else {
            // 后续的 chunk，追加 arguments 碎片
            toolCalls[realIdx].Function.Arguments += tc.Function.Arguments
        }
    }

    // 文字内容直接打印到终端
    if delta.Content != "" {
        fmt.Print(delta.Content)
    }
}
```

### 步骤 6: 判断是否有工具调用

**文件**: `llm.go:94-101`

```go
if len(toolCalls) == 0 {
    // 没有工具调用，对话结束
    return nil
}
```

- `toolCalls` 为空 → LLM 直接回复了文字，本轮对话完成
- `toolCalls` 不为空 → 需要执行工具

### 步骤 7: 把工具调用意图加入消息历史

**文件**: `llm.go:103-105`

```go
messages = append(messages, buildAssistantMessageWithToolCalls(textBuf.String(), toolCalls))
```

构建一条 `assistant` 消息，告诉 LLM"我刚才说要调用这些工具"。

### 步骤 8: 执行每个工具

**文件**: `llm.go:107-137`

对每个 `tool_call`，执行 4 步：

```go
for _, tc := range toolCalls {
    // 1. 解析参数（JSON 字符串 → map）
    args, err := ParseToolArgs(tc.Function.Arguments)

    // 2. 根据工具名找到对应的 Go 函数
    toolFunc := GetToolFunc(tc.Function.Name)

    // 2.5 bash 工具特殊处理：替换为带确认回调的版本
    if tc.Function.Name == "bash" && c.confirmFunc != nil {
        toolFunc = GetBashToolFunc(c.confirmFunc)
    }

    // 3. 执行工具函数
    result := toolFunc(args)

    // 4. 把结果加入消息历史（用 tool_call 的 id 关联）
    messages = append(messages, openai.ToolMessage(result.Raw, tc.ID))
}
```

### 步骤 9: 循环回到步骤 3

**文件**: `llm.go:139`

```go
// Loop back to call LLM again with tool results
```

此时 `messages` 是这样的：

```
[
  user("帮我看看 main.go 的内容"),
  assistant(tool_calls: [{name: "read_file", args: {path: "main.go"}}]),
  tool("package main\n\nimport ...", tool_call_id: "call_abc123")
]
```

再次调用 LLM。LLM 看到工具返回了文件内容，会生成文字回复（不再调用工具），流程结束。

## 6. 常见问题解答

### Q: 为什么 LLM 返回 tool_calls 后，我还要再调一次 LLM？

因为 LLM **不会直接执行工具**。它只是一个文本生成模型。它告诉你"我想调用 read_file，参数是 path=main.go"，你需要：
1. 自己执行这个操作
2. 把结果以 `tool` 消息的形式告诉它
3. 再次调用它，让它根据结果生成最终回复

这就是为什么 `Chat` 方法里有一个 `for` 循环。

### Q: tool_call_id 是干什么的？

当 LLM 调用工具时，会给每个调用生成一个唯一 `id`（如 `call_abc123`）。你把工具结果返回给 LLM 时，必须带上这个 `id`，这样 LLM 才知道"这个结果是哪个工具调用的回复"。

```
assistant: 我想调用 read_file(path="main.go")  [id: call_abc123]
tool: "package main..."                          [tool_call_id: call_abc123]  ← 关联上
```

### Q: 为什么要有 for 循环？不能一次搞定吗？

不能。一次 API 调用只能得到一个回复。如果 LLM 要调用工具，你需要：
1. 第1次 API 调用 → LLM 说"我要调工具"
2. 你执行工具
3. 第2次 API 调用 → 把工具结果给 LLM → LLM 生成最终回复

如果 LLM 在第2次又决定调另一个工具，还需要第3次... 所以必须用循环。

### Q: 多个工具调用是并行还是串行？

在当前代码中是**串行**的（`llm.go:108` 的 for 循环）。LLM 一次可能要求调用多个工具（如同时调 `read_file` 和 `bash`），我们按顺序执行，把结果一起返回。

### Q: bash 工具的安全确认是怎么工作的？

`llm.go:130-132`：当检测到工具名为 `bash` 且有 `confirmFunc` 回调时，用 `GetBashToolFunc(c.confirmFunc)` 替换默认的工具函数。

这个替换后的函数在执行命令前会：
1. 调用 `isDangerousCommand()` 检查黑名单
2. 如果命中，调用 `confirmFunc(command, riskType)` 向用户弹窗确认
3. 用户输入 `y` 才放行，否则拒绝执行

整个确认过程**发生在工具执行阶段**，不影响 LLM 的 API 调用流程。

## 7. 一句话总结

**工具调用的本质**：你和 LLM 之间的"对话回合"。LLM 说"我想用这个工具"，你执行后把结果告诉它，它再生成最终回复。`for` 循环确保这个对话可以持续多个回合，直到 LLM 不再需要工具为止。

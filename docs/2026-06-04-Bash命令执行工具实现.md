# Bash 命令执行工具实现

> 创建日期: 2026-06-04

## 1. 需求背景

AI 助手需要能够执行系统命令，以实现更强大的自动化能力，例如：
- 查看目录结构
- 检查 git 状态
- 运行构建/测试命令
- 安装依赖

## 2. 实现方案

### 2.1 工具定义

在 `internal/tools.go` 的 `GetTools()` 中添加 `bash` 工具定义：

```go
map[string]any{
    "type": "function",
    "function": map[string]any{
        "name":        "bash",
        "description": "Execute a bash command and return its output (stdout and stderr).",
        "parameters": map[string]any{
            "type": "object",
            "properties": map[string]any{
                "command": map[string]string{
                    "type":        "string",
                    "description": "The bash command to execute.",
                },
            },
            "required": []string{"command"},
        },
    },
},
```

### 2.2 函数签名

```go
type ToolFunc func(args map[string]any) ToolResult

type ToolResult struct {
    Success bool
    Raw     string
}
```

### 2.3 核心实现

```go
func bashCommand(args map[string]any) ToolResult {
    command, ok := args["command"].(string)
    if !ok {
        return ToolResult{Success: false, Raw: "missing required argument: command"}
    }

    cmd := exec.Command("bash", "-c", command)
    output, err := cmd.CombinedOutput()
    if err != nil {
        return ToolResult{Success: false, Raw: string(output) + "\nError: " + err.Error()}
    }

    return ToolResult{Success: true, Raw: string(output)}
}
```

### 2.4 注册到工具路由

在 `GetToolFunc()` 中添加：

```go
case "bash":
    return bashCommand
```

## 3. 安全风险

为 AI 助手开放 Bash 执行能力存在重大安全风险：
- AI 可能执行危险命令（如 `rm -rf /`、格式化磁盘等）
- 用户输入被恶意构造时可能导致命令注入
- AI 幻觉可能导致误操作

## 4. 危险命令阻止机制

### 4.1 黑名单过滤（当前采用）

维护一个危险命令正则表达式黑名单（`dangerousPatterns`），在执行前进行检查。

#### 黑名单类别

| 类别 | 正则表达式 | 示例 |
|------|-----------|------|
| 危险删除 | `(?i)\brm\s+(-[a-zA-Z]*r[a-zA-Z]*f[a-zA-Z]*\|-[a-zA-Z]*f[a-zA-Z]*r[a-zA-Z]*)\s+` | `rm -rf /`, `rm -fr ~/` |
| 根目录删除 | `(?i)\brm\s+-rf\s+/$`, `(?i)\brm\s+-rf\s+/(\s\|$)` | `rm -rf /` |
| Home 删除 | `(?i)\brm\s+-rf\s+~` | `rm -rf ~` |
| 安全擦除 | `(?i)\bshred\b` | `shred -n 3 file` |
| 磁盘格式化 | `(?i)\bmkfs\.`, `(?i)\bmkfs\b` | `mkfs.ext4 /dev/sda1` |
| 磁盘分区 | `(?i)\bfdisk\b` | `fdisk /dev/sda` |
| 磁盘写入 | `(?i)\bdd\s+if=/dev/zero\b`, `(?i)\bdd\s+if=/dev/null\b` | `dd if=/dev/zero of=/dev/sda` |
| 危险权限 | `(?i)\bchmod\s+-?777\b`, `(?i)\bchmod\s+-?776\b` | `chmod 777 /` |
| 递归属主 | `(?i)\bchown\s+-R\b` | `chown -R root:root /` |
| 防火墙清空 | `(?i)\biptables\s+-F\b` | `iptables -F` |
| 防火墙禁用 | `(?i)\bufw\s+disable\b` | `ufw disable` |
| 停止服务 | `(?i)\bsystemctl\s+stop\b` | `systemctl stop sshd` |
| 强制杀死进程 | `(?i)\bkill\s+-9\b` | `kill -9 1234` |
| 覆盖关键文件 | `(?i)\bmv\s+.+\s+/etc/passwd\b` | `mv /tmp/evil /etc/passwd` |
| Fork Bomb | `:\{\s*:\|:&\s*\};:` | `:(){ :|: & };:` |

#### 核心实现

```go
// isDangerousCommand 检查命令是否在黑名单中。
func isDangerousCommand(cmd string) (bool, string) {
    trimmed := strings.TrimSpace(cmd)
    for _, pattern := range dangerousPatterns {
        if pattern.MatchString(trimmed) {
            return true, "command blocked by safety filter: " + pattern.String()
        }
    }
    return false, ""
}
```

在 `bashCommand` 中集成：

```go
func bashCommand(args map[string]any) ToolResult {
    // ...
    // 危险命令检查
    if dangerous, reason := isDangerousCommand(command); dangerous {
        slog.Warn("dangerous command blocked", "command", command)
        return ToolResult{Success: false, Raw: "dangerous command blocked: " + reason}
    }
    // ... 执行命令
}
```

### 4.2 方案二：白名单模式（未来可选）

只允许预定义的命令子集，如 `ls`, `cat`, `git`, `go build` 等。适用于对安全要求极高的场景。

### 4.3 方案三：交互式确认（当前采用）

**核心思路**：黑名单不再直接拦截，而是作为"需确认命令"的判定依据。当命令命中黑名单时，暂停执行，向用户展示命令内容及风险类型，等待用户输入 `y`/`yes` 确认后才放行。

#### 交互流程

```
AI 调用 bash 工具
       ↓
bashCommand() 解析参数
       ↓
isDangerousCommand() 检查
       ↓
   命中？
   ├── 否 → 直接执行命令 → 返回结果
   └── 是 → 暂停，返回确认提示
              ↓
         Chat Loop 提示用户: "⚠ 该命令命中安全规则 [xxx]，是否执行？(y/n)"
              ↓
         等待用户输入
              ├── y/yes → 执行命令 → 返回结果
              └── n/其他 → 拒绝执行 → 返回 "用户已拒绝执行该命令"
```

#### 数据结构变更

需要引入一个新的返回状态，区分"正常结果"、"待确认"、"用户拒绝"：

```go
type ToolResult struct {
    Success  bool
    Raw      string
    NeedConfirm bool   // 是否需要用户确认
    RiskType string   // 命中的风险类别
}
```

或者采用更简洁的方式：在 `Raw` 中使用特殊前缀标记待确认状态，由 `Chat` 循环解析并处理。

#### 实现方案

**方式一：ToolResult 扩展状态**

在 `bashCommand` 中，命中黑名单时返回：

```go
return ToolResult{
    Success:     false,
    Raw:         fmt.Sprintf("[CONFIRM_REQUIRED] 该命令命中安全规则: %s\n命令: %s\n是否继续执行？(y/n)", reason, command),
    NeedConfirm: true,
    RiskType:    riskType,
    Command:     command, // 保存原始命令，确认后重新执行
}
```

**方式二：Chat Loop 介入确认**

修改 `Chat` 循环，当收到 `ToolMessage` 中包含 `[CONFIRM_REQUIRED]` 前缀时：
1. 暂停 LLM 调用
2. 向用户展示确认提示
3. 根据用户输入决定：
   - 用户确认 → 重新调用 `bashCommand`（带确认标记跳过检查）
   - 用户拒绝 → 将 "用户已拒绝" 作为 ToolMessage 返回给 LLM

**方式三：回调机制（推荐）**

在 `bashCommand` 中注入一个确认回调函数：

```go
type ConfirmFunc func(command, riskType string) bool

type BashTool struct {
    Confirm ConfirmFunc
}

func (b *BashTool) bashCommand(args map[string]any) ToolResult {
    // ...
    if dangerous, reason := isDangerousCommand(command); dangerous {
        if b.Confirm == nil || !b.Confirm(command, reason) {
            return ToolResult{Success: false, Raw: "用户已拒绝执行该命令"}
        }
    }
    // ... 执行命令
}
```

#### Chat Loop 确认交互实现

在 `cmd/main.go` 的对话循环中处理确认：

```go
// 解析 ToolMessage 是否需要确认
if strings.Contains(result.Raw, "[CONFIRM_REQUIRED]") {
    fmt.Println()
    fmt.Printf("⚠  安全确认: %s\n", extractConfirmMessage(result.Raw))
    fmt.Print("是否执行？(y/n): ")

    if !scanner.Scan() || !userConfirmed(scanner.Text()) {
        messages = append(messages, openai.ToolMessage("用户已拒绝执行该命令", tc.ID))
        continue
    }
    // 用户确认，重新执行（跳过确认检查）
    result = toolFunc(args) // 带 skipConfirm=true
}
```

## 5. 数据流

### 5.1 安全命令数据流

```
AI 调用 bash 工具
       ↓
ParseToolArgs 解析参数
       ↓
GetToolFunc("bash") → bashCommand()
       ↓
isDangerousCommand() 检查
       ↓
   命中？
   ├── 否 → exec.Command("bash", "-c", command)
   │            ↓
   │       CombinedOutput() → 返回 stdout+stderr
   │            ↓
   │       ToolMessage 返回给 LLM
   │
   └── 是 → 返回 [CONFIRM_REQUIRED] 标记
                ↓
           Chat Loop 捕获确认请求
                ↓
           展示给用户: "⚠ 安全确认: ..."
                ↓
           等待用户输入 (y/n)
                ├── y/yes → 重新执行 (skipConfirm=true) → ToolMessage 返回 LLM
                └── n/其他 → ToolMessage("用户已拒绝") 返回 LLM
```
